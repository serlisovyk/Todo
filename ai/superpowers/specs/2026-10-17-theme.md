# Spec: the theme, light, dark or system (MY-157)

Decisions in force: `theme-three-states` (the three positions, the circle), `theme-head-script` (the
script that sets the theme before the first paint), `design-tokens` and `plain-css-and-tokens` (both
themes already exist as tokens; no `prefers-color-scheme` block), `context-folders` and
`structure-and-naming` (where the files go), `repository-storage-restore` (storage access stays in
`storage/`), `errors-as-toasts` (a refused write is a toast), `list-animations` (the View Transition
rules the circle follows), `accessibility-and-seo` (WCAG 2.2 AA) and `js-budget-90-kb`. Nothing here changes a stored task.

## The switch

The header's right end holds a group of three round buttons: a sun, a moon and a monitor. They are
native radio buttons, so exactly one is selected, and the selected one is filled with the accent
colour in both themes.

| Button  | Sets     | Name for assistive technology |
| ------- | -------- | ----------------------------- |
| Sun     | `light`  | "Light theme"                 |
| Moon    | `dark`   | "Dark theme"                  |
| Monitor | `system` | "System theme"                |

- The group is named "Theme". The icons are decorative; the names above are visually hidden text.
- The selected button is the saved choice; with nothing saved it is the monitor. A screen reader
  says the name, "radio button", "checked" and the position, for example "Light theme, 1 of 3".
- Tab enters the group once, on the selected button; the arrow keys move the selection and the
  focus together and wrap at the ends, as in any native radio group. The change is applied the
  moment the selection moves.
- Every button is at least 44px square. The focus ring is the base one, drawn around the button.
  The selected state is the fill, not the colour of the icon alone, and in forced colours mode it is
  still visible.
- The group is at the end of the header on the same row as the logo and the title, from 320px up,
  with no horizontal scroll at 200% zoom.

## What each position does

- `light` and `dark` show that theme.
- `system` shows the theme of the operating system and follows it live: while it is selected, a
  change of the OS theme changes the page at once, with no reload and without a circle. While `light`
  or `dark` is selected, a change of the OS theme does nothing.
- The page is always in exactly one of the two looks: `<html data-theme>` is `light` or `dark`,
  never missing and never `system`.

## Persistence

- The choice is saved in `localStorage` under `todo:theme` as `light`, `dark` or `system` the moment
  it changes. A reload keeps it.
- A missing, unknown or unreadable value means `system`. Nothing is written at start.
- When the browser refuses the write (full or blocked storage), the theme still changes on screen,
  the app keeps working, and an error toast (the danger icon and a readable message, announced by the
  toast region) says so. The choice is then not remembered after a reload.
- A choice made in another tab is not followed; this tab picks the saved choice up on its next load.

## The first paint

- A blocking script in `<head>`, before anything is painted, reads `todo:theme`, resolves `system`
  with the OS preference and sets `<html data-theme>`. No frame of the production page is drawn in
  the other theme, with any saved value and with none.
- If reading storage throws, the script falls back to the OS preference; if the script fails to load,
  the page is light.
- The script is the only code outside `storage/` that reads `localStorage`. Its key and values are
  literals that equal the constants of the app.

## The browser chrome

- `color-scheme` follows the theme, so the scrollbars, the form controls and the canvas match it
  (already done in the tokens).
- `<meta name="theme-color">` holds the page background of the current theme, the value of
  `--color-page`, so the address bar of a phone matches the page. It changes with every theme change,
  also when the OS changes it under `system`. Until the app starts the tag has no colour.

## The circle

- Choosing a button reveals the new theme as a circle that grows from the centre of that button to
  cover the page in 200ms, the base duration token. The old theme stays underneath.
- No circle, and an instant change, under `prefers-reduced-motion: reduce` and in a browser without
  `document.startViewTransition`; the second case never errors.
- The circle never drops a choice: choosing again by keys while it runs starts the next circle and
  the newest choice wins. While it runs, 200ms, the browser does not deliver clicks and taps to a
  page whose root is in a View Transition, so a click in that window has to be repeated; keys are
  not affected. A change of the OS theme under `system` has no circle.

## Out of scope

Editing and deleting tasks, list animations, a
theme choice synced between tabs, more than two looks, a per-component theme, a PWA manifest colour.
