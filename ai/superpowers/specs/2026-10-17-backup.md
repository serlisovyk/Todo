# Spec: export and import of the tasks as a JSON file (MY-160)

Decisions in force: `export-and-import` (refined by the new record `backup-export-import`: the
buttons leave the footer, the summary is split), `todo-model` (the task fields), `repository-storage-restore`
(`restore` writes tasks back unchanged and skips stored ids), `errors-as-toasts` (a failed write is an
error toast), `footer-acts-on-all-tasks`, `tooltips-as-title`, `accessibility-and-seo` (WCAG 2.2 AA, both
themes) and `js-budget-90-kb`. Search, the Filters panel and list animation are other tasks.

## The row

The last thing in `<main>`, under the list and the footer, always on screen: a group named "Backup" with two
text buttons, Export and Import, in this order. The footer is not changed.

- Import is always there, also with no tasks: it is how an empty app (a new browser, the other storage) is
  filled.
- Export is there only while at least one task exists, and it takes all tasks, whatever the status filter
  shows (`footer-acts-on-all-tasks`).
- Both are real `<button type="button">` named by their visible text.

## Export

- Export downloads `todo-backup-YYYY-MM-DD.json`, the date being today's local date, through a `Blob` and an
  `<a download>`; nothing leaves the browser.
- The content is one JSON object, compact (no indentation):
  `{ "app": "todo", "version": 1, "exportedAt": "<ISO time of the click>", "todos": [ ... ] }`. `version` is
  the stored data format version, the same number `todo:data` carries; `todos` holds every task with every
  field, as the app has them.
- No toast: the download is the browser's own feedback and no app state changes.

## Import

Import opens a hidden file picker (`accept=".json,application/json"`, one file). The input is hidden from the
tab order and from assistive technology, so the button is the only control. After each choice the picker is
reset, so the same file can be chosen again.

The file is checked as a whole first, in this order; the first check that fails ends the import with an error
toast and nothing is written:

| Check                                                                                        | Toast                                        |
| -------------------------------------------------------------------------------------------- | -------------------------------------------- |
| the file is at most 1 MB (`file.size`, before the file is read)                              | That file is too large to import (over 1 MB) |
| the file can be read                                                                         | That file could not be read                  |
| it is JSON: an object, `app` is `todo`, `version` is the format version, `todos` is an array | That file isn't a Todo backup                |

A text that is not JSON at all, `null`, an array and another app's JSON all fail the third check.

Then each task goes through the same validator the storage uses (`sanitizeTodo`): a broken task (not an object,
a wrong or missing field, an empty or too long title) is skipped, the title is trimmed and fields the app does
not know are dropped.

The tasks merge by `id`, with no confirmation:

- A valid task whose `id` is not among the app's tasks is added as it is in the file (same `id`, `createdAt`,
  every field) through the repository's `restore`.
- A task whose `id` is already there is left untouched, never overwritten. A second task in the file with an
  `id` the file already used counts the same way: the first one is kept.
- All the new tasks are written by one call: all of them or none. A refused write puts the list back and shows
  the storage error toast, with no summary.

The summary is a plain toast (no icon, no button) of the parts that are not zero, in this order, joined by
", ": `Imported 8 tasks`, `2 already there`, `1 skipped`. The noun follows the count (`1 task`, `2 tasks`).
When nothing new was imported but another part exists, the message starts with `Nothing new: `.

| File                       | Toast                                        |
| -------------------------- | -------------------------------------------- |
| 8 new, 2 present, 1 broken | Imported 8 tasks, 2 already there, 1 skipped |
| 1 new                      | Imported 1 task                              |
| the same file again        | Nothing new: 8 already there                 |
| 2 present, 1 broken        | Nothing new: 2 already there, 1 skipped      |
| only broken tasks          | Nothing new: 3 skipped                       |
| `todos` is an empty array  | That backup has no tasks                     |

A toast replaces the one that is on screen, like every toast.

## Between the storages

The file has one format for both storages. Exported from the localStorage app and imported into the app that
runs with `VITE_STORAGE=indexeddb`, it brings every task with its `id` and its timestamps, and importing it
again adds nothing.

## What a screen reader hears

- The group is named "Backup"; each button's name is its text. The file picker is the browser's.
- The result of an import, error or summary, is one message in the toast's polite `role="status"` region and
  is read once. Export says nothing: the browser announces its download.

## Focus

Nothing moves the focus. The Import button keeps it across the picker (the browser hands it back) and while
the result is shown; the first import into an empty app makes Export appear to its left and the focus stays
on Import.

## Look

The row follows the footer's edges, right-aligned. Its buttons are the shared text button, the same as the
footer's and the toast's action: small text, accent colour, 44px tall, hover only where the device can hover. Colours, spacing and radii are tokens; contrast holds
in both themes. At 320px the buttons stay on one line or wrap with no horizontal scroll.

## Out of scope

Undo for an import, a mode that replaces the tasks, a confirmation, drag and drop of the file, other formats,
export of the filtered list only, migrating older backups (the migration table appears with the first format
change, `ai/skills/storage.md`), and a toast on export.
