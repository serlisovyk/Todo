# Spec: search with highlighted matches (MY-155)

Decisions in force: `filters-and-search` (the query is a URL parameter like the status, the search
is case-insensitive on the title, matches go into `<mark>` without `dangerouslySetInnerHTML`, `/`
focuses the search, `Escape` clears it, the placeholder carries the hint), `footer-acts-on-all-tasks`
(the counter and the buttons ignore the query), `tooltips-as-title` (the clear button is named by its
`title`), `design-tokens` (`--color-highlight` and `--color-on-highlight`), `accessibility-and-seo`
(WCAG 2.2 AA, both themes) and `js-budget-90-kb`. Category, sort and the Filters panel (MY-156), list
animation (MY-158) and export and import (MY-160) are other tasks.

## The field

Between the add form and the status switch, always on screen, tasks or none. It is as wide as the
content column and 44px tall, outlined like the add form's title field.

- A visually hidden label "Search tasks"; the Lucide `Search` icon at the start, decorative; the
  placeholder "Search tasks (press /)", which is the hint for the shortcut.
- A clear button at the end, an icon-only 44px button named "Clear search" by its `title`, which is
  also its tooltip. It is there only while the field holds text: nothing to clear, no button.
- The field says exactly what was typed. Clearing it with the button or `Escape` empties it and the
  focus stays in the field (the button, which disappears, hands it back).
- A screen reader says "Search tasks", the field's kind, and that `/` is its shortcut
  (`aria-keyshortcuts`); the button is "Clear search", read once.

## The query and the URL

- The query is the parameter `q`, next to `status`: `?q=report`, `?status=active&q=report`. It is
  written on every keystroke with `history.replaceState`, no debounce, no new history entry; a change
  of one parameter leaves the other as it is.
- A query that is empty or only spaces is the default and is never written, so clearing leaves a
  clean URL. Nothing is written at start; any other text in `?q=` is a query, there is no unknown
  value to ignore.
- A reload keeps the search: the field shows the text and the list is filtered. The URL keeps the
  text as typed, so a space typed between two words survives; the filter ignores the spaces at the
  ends (see the list).

## The list

- A task is shown when its title contains the query, ignoring case, and its status matches. The
  query is trimmed first: " rep " finds what "rep" finds; spaces inside a query count.
- The order is the usual one. Status and search combine; the footer does not follow either
  (`footer-acts-on-all-tasks`).
- "rep" keeps "Report", "Prepare slides" and "Repay the loan" and drops the others. With no task left
  the card says "No tasks match your filters." The empty list still says "No tasks yet. Add your first
  one above.", whatever the query.
- A task added while a search hides it is stored and not shown; the form still says "Task added".
- Checking a task never changes whether the query matches it, so the focus rule of the status filter
  needs no change. Saving an edit so that the new title no longer matches removes the row: the focus
  first goes where delete sends it (the next row's checkbox, else the previous one, else the checked
  status radio) instead of the edit button the row is about to lose.

## The highlight

- Every occurrence of the query in a title is wrapped in `<mark>`, left to right, in the case the
  title has. "a" in "Banana" marks three letters. No match, no `<mark>`; an empty query marks
  nothing.
- Characters of the query are plain text: `(`, `*`, `.`, `\`, `[`, `$` match themselves and break
  nothing; "(_.)" simply finds titles containing "(_.)", and none is fine.
- The title is rendered as text parts and `<mark>` elements, never as HTML: a title such as
  `<b>x</b>` shows its characters.
- While a row is being edited it is the plain edit field: no highlight. The names of the Edit and
  Delete buttons stay the plain title.
- Look: `--color-highlight` fills the match and `--color-on-highlight` colours its text. The light
  theme has a pale yellow with near-black text (14:1); the dark theme a muted dark gold with
  near-white text (4.9:1), the fill itself 3.4:1 against the card and 3.1:1 against a hovered row.
  In forced colours the fill is `Highlight` and the text `HighlightText`. A completed task's
  strikethrough runs through the mark.

## The keyboard

- `/` moves the focus to the search from anywhere outside an editable field, and the slash is not
  typed. In a text field, a textarea or a `<select>` (the `EDITABLE_FIELD_SELECTOR` the undo
  shortcut already skips) it is an ordinary character. With Ctrl, Cmd or Alt held it is left to the
  browser; Shift does not matter, because some layouts type `/` with it.
- `Escape` in the field clears it and does nothing when it is empty. Escape while editing a task
  still cancels the edit; the two never happen together, because the edit closes when the field is
  left.
- Tab order: the form, the search field, its clear button, the status radios.

## What a screen reader hears

One persistent visually hidden polite region (`role="status"`) sits above the list, after the status
switch, and stays in the page whatever the list shows. It is shared by the status, the search and the
Filters panel of MY-156.

- It says "N tasks shown" ("1 task shown", "3 tasks shown") or "No tasks match your filters", the
  number being the rows on screen.
- It speaks when the filters change: choosing another status, and every change of the query that is
  not only spaces at its ends. A second filter change with the same result is read again.
- It does not speak on load, also when the URL already holds a status or a query, and not while the
  tasks load. It does not speak when the tasks change under unchanged filters (adding, checking,
  deleting, marking all, Undo, editing): those have the form's message, the counter and the toast, and
  one change is read once. With no tasks at all it says nothing, the list says "No tasks yet".
- Typing reads the result on each change of the query, without a delay; that is the author's
  choice.

## Look

Colours, spacing and radii from the tokens, both themes. The icon and the button sit inside the
field's border without covering the text: the field keeps room for both. At 320px the field takes the
width of the column, the placeholder fits, nothing scrolls sideways, and at 200% zoom the field and
the button stay usable. Hover only where the device can hover. Reduced motion needs nothing of its
own: the field animates nothing.

## Out of scope

Category, sort and the Filters panel (MY-156), list animation (MY-158), export and import (MY-160),
a debounce, a visible result count, search history, matching by word, by accent or by fuzzy
likeness, and searching the category or priority names.
