# Plan: accessibility and responsive audit (MY-161)

Branch `my-161-audit`. Linear issue MY-161, milestone Аудит, after MY-156, MY-157, MY-158, MY-160 and MY-166 (the
whole interface exists). The findings, their WCAG criteria and the evidence are in
`ai/superpowers/specs/2026-10-18-audit.md`; this plan is how they are fixed and checked. Decisions in force:
`accessibility-and-seo`, `design-tokens`, `tooltips-as-title`, `base-select-pickers`, `filter-pills`,
`search-shortcut-key`, `list-motion-without-view-transitions`, `errors-as-toasts`, `theme-three-states`.

## The author's answers (issue, «Решения автора», 2026-10-16 and 2026-10-18)

- Target WCAG 2.2 AA, Lighthouse 100, zero axe violations, both themes.
- Lighthouse and axe run once, outside the project (`npx`, axe-core injected over the DevTools protocol); nothing
  is added to `package.json` or the lockfile.
- Firefox and WebKit come from Playwright's own cache and are driven by a script outside the repository. WebKit is
  not Safari. NVDA is not run: speech is read from the accessibility tree and the live regions, and NVDA is
  reported as unverified.
- Every finding is fixed on this branch in its own commit. A fix that changes behaviour, or needs a choice, is not
  guessed: it goes to the author as a question with options and a recommendation, and its commit waits.

## Method

Headless Chrome 155 over the DevTools protocol (seeded `localStorage`, both themes), Firefox 157 and WebKit 27.2
through Playwright. Scripts and screenshots live in the session scratchpad, not in the repository.

- Keyboard: the Tab order, then add, edit (Enter, Save, Cancel, Escape, leaving), toggle, delete and Undo
  (button and Ctrl+Z), the status radios, search and `/`, the pills and Reset, the theme, export and import, the
  footer; after each step the focused element and every live-region change.
- Layout matrix: content widths 240, 256, 290, 305, 320, 375, 479, 480, 640, 740×360 and 1280, text at 100%,
  150% and 200%, states list, filtered, edit form, toast, validation error; the viewport is widened by the
  scrollbar so the content width is the stated one. Horizontal overflow, wrapped status switch, targets under 44px.
- Contrast: every text, border, icon and focus ring of every state (hover and focus forced), both themes,
  computed from the rendered colours.
- Forced colors (Chrome's emulation; it found A3 to A5, see the report), reduced motion, text spacing (WCAG 1.4.12),
  phone landscape, touch taps.
- Lighthouse and axe on `pnpm preview` and, once, on the deployment of `main` (read-only).

## Fixes, one commit each

1. Edit form: Escape inside an open picker closes the picker only.
2. Edit form: it closes after the pointer is released, so the control below it still gets its click; touch too.
3. Forced colors (A3 to A5): no fix. The author decided they are out of scope, so the existing `forced-colors`
   styles go too, in one `refactor:` commit with the scope line.
4. Tokens: `--color-border-control` reaches 3:1 on the hovered row in both themes.
5. Layout: the focused control stays clear of the toast (scroll padding and bottom space).
6. Layout: the header wraps, the theme switch and the pills shrink, the status switch sizes its columns by their
   labels (one row down to 240px, equal columns when there is room; the author's answer to Q1).
7. Search field: the placeholder gets the clear button's room while it is empty.
8. Pills: an open picker shows no tooltip of the label.
9. Docs: `definition-of-done.md`, `skills/review.md`.
10. Search: the filter result is announced only when its text changes (the answer to Q3).
11. Docs: the decision `undo-toast-time-limit` (the answer to Q2).

Not done here, by decision of the author or because another task owns it: the favicon and the SEO tags (MY-162);
the Undo toast's 5 seconds (Q2, recorded instead); the `replaceState` limit of Safari's engine (Q4, a known and
accepted limitation).

## Docs

- `ai/rules/definition-of-done.md`: the hover state in the contrast point, a fixed overlay never covering the
  focused control, 200% text at 320px, and a control that must not move between pointer down and up.
- `ai/skills/review.md`: the same as checks, and the verification gaps they close.
- `ai/rules/scope.md`: one line, Windows contrast themes (`forced-colors`) are not tuned, out of scope by the
  author's decision; `ai/rules/style.md` loses its forced-colors colour rule.
- `ai/map.md`: the `keyboard.constants.js` line, which now holds more than the editable-field selector.
- `ai/decisions/2026-10-18-undo-toast-time-limit.md` (new, in the index): the one conscious exception the audit
  found, WCAG 2.2.1 for the Undo toast. `search-shortcut-key` was checked against the code and is accurate.
- `ai/rules/react.md` and `ai/skills/feature.md`: the filter result speaks only when its text differs from the last
  one; `ai/skills/review.md` says the same as a check. No old record says a repeated result is read again.
