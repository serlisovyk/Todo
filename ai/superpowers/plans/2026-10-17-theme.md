## Code

Layers and names follow `structure-and-naming` and `context-folders`; each new folder gets its
`index.js` with its first file.

- `public/theme.js` — a classic script in an arrow IIFE (no globals leak): reads `todo:theme` inside a
  `try`, resolves anything but `light` and `dark` with `matchMedia('(prefers-color-scheme: dark)')`,
  sets `document.documentElement.dataset.theme` to `light` or `dark`. No comments, as everywhere.
- `index.html` — `<meta name="theme-color" content="" />` and `<script src="/theme.js"></script>` in
  `<head>` before the font preload and before the stylesheet Vite appends. Vite copies `public/`
  as it is, and `pnpm preview` serves it.
- `eslint.config.js` — the storage restriction moves from `src/**` to every `**/*.{js,jsx}` and its
  `ignores` become `src/storage/**` and `public/theme.js`, so the config says exactly where the
  exception is: any other file, a new one in `public/` included, is still checked.
- `src/constants/theme.constants.js` — everything of the theme, the storage key and the save message
  included: `THEME_STORAGE_KEY` (`todo:theme`), `THEME_LIGHT`, `THEME_DARK`, `THEME_SYSTEM`, `THEMES`
  (an `{ id, label, Icon }` per button, in their order, the labels are the names above and the `Icon`
  is the `lucide-react` icon), `DEFAULT_THEME`, the two media queries, the three CSS variable names
  the code reads (`--color-page`, `--duration-base`, `--ease-out`), the `theme-color` selector, the
  circle's pseudo-element, `SAVE_THEME_ERROR_MESSAGE` and `MISSING_THEME_PROVIDER_MESSAGE`. It is
  re-exported from `constants/index.js`; the storage constants stay the tasks'.
- `src/constants/css.constants.js` — the two time units `toMilliseconds` reads, `MILLISECOND_UNIT`
  and `MILLISECONDS_PER_SECOND`: they are CSS values, not theme values.
- `src/utils/theme.utils.js` — `isTheme(value)` and `resolveTheme(theme, isSystemDark)`: pure, one
  home for what a valid choice is and which look a choice means. `src/utils/css.utils.js` —
  `toMilliseconds(time)`: a token is read as text, and the production build rewrites `200ms` to
  `.2s`, so the unit is honoured instead of read with a bare `parseFloat`. Both are re-exported from
  `utils/index.js`.
- `src/storage/theme.repository.js` — `ThemeRepository`: `read()` returns the stored choice when
  `isTheme` accepts it and `DEFAULT_THEME` for anything else, a thrown read included; `save(theme)`
  writes it and throws a readable `Error` (with the original as `cause`) when the browser refuses.
  Both are synchronous: the first paint needs the saved choice without waiting. It holds no state
  and no helper, so the file is the imports and the two methods.
- `src/storage/index.js` — also exports `ThemeRepository` itself. `createRepository` exists to choose
  between two implementations; the theme has one, so a factory would be a function that only calls
  `new`. The provider keeps the instance in `useState`, like the tasks' provider keeps its repository.
- `src/context/theme/use-media-query.js` — `useMediaQuery(query)` over `useSyncExternalStore`: the
  snapshot is `matchMedia(query).matches`, the subscription is the query's `change` event with its
  `removeEventListener` as cleanup. No effect and no copy in state, so a change re-renders at once.
- `src/context/theme/use-circle-transition.js` — `useCircleTransition()` returns a function that takes the
  `update` and the `origin` element. Without `document.startViewTransition`, or under
  `prefers-reduced-motion: reduce`, it calls `update()` and returns. Otherwise it takes the centre of
  `origin` and the distance to the farthest corner, calls
  `document.startViewTransition(() => flushSync(update))`, and when the transition is ready animates
  the `clip-path` of `::view-transition-new(root)` from a zero circle to the full one through the Web
  Animations API, with the duration and easing read from `--duration-base` and `--ease-out`. A failed
  `ready` is caught: the update has already run in the callback, so a choice is never lost, and a
  newer transition simply skips the older one.
- `src/context/theme/` — `theme.context.js`; `theme.provider.jsx` (`ThemeProvider`); `use-theme.js`
  (`useTheme`, throws outside the provider); the two private hooks above; `index.js` exports only the
  provider and the hook; `context/index.js` re-exports it. `hooks/` is untouched. `ThemeProvider`:
  - calls `useToast()` (through `@/context/toast`), keeps the `ThemeRepository` in `useState` and the
    choice in `useState(() => repository.read())`;
  - `isSystemDark = useMediaQuery(DARK_SCHEME_QUERY)` and `resolveTheme(theme, isSystemDark)` give
    the look, derived on every render and never stored;
  - one effect keyed by the look sets `document.documentElement.dataset.theme` and then copies the
    computed `--color-page` into the `theme-color` meta, so every cause of a change (a click, the OS)
    goes through the same place;
  - `changeTheme(nextTheme, origin)` runs `runCircleTransition(() => setTheme(nextTheme), origin)`
    first, then `repository.save(nextTheme)` in a `try` whose `catch` calls
    `showToast({ message: saveError.message, isError: true })`; it never throws;
  - the context value is `{ theme, changeTheme }`.
- `src/components/theme-switch/` — `theme-switch.jsx`, `theme-switch.css`, `index.js`. A `<fieldset>`
  with an `.sr-only` `<legend>` "Theme" and one `<label>` per `THEMES` entry: the radio `<input>`
  (`name="theme"`, `checked={theme === id}`), the icon and an `.sr-only` name. `onChange` calls
  `changeTheme(event.target.value, event.currentTarget)`. A component file holds only its imports
  and the component, so the icons come from `THEMES`.
  `components/index.js` re-exports it.
- `src/components/app-header/` — renders `<ThemeSwitch />` after the title, imported from its folder
  barrel; the stylesheet pushes it to the end of the row.
- `src/components/app/app.jsx` — `ThemeProvider` sits inside `ToastProvider`, around `TodosProvider`.
- `src/styles/animations.css` (new, imported last by `style.css`) — the two `::view-transition-*`
  rules of `root` that turn off the default cross-fade and its blending, so the circle is the only
  animation. It holds no `@keyframes` yet.

### How the switch looks

The group is a pill: `--color-surface`, a `--color-border` outline, `--radius-full`, a `--space-1`
padding and gap. Each radio is `appearance: none`, `--touch-target` square and round, the way the task
checkbox is drawn: the icon sits over it (same grid cell, `pointer-events: none`), muted by default and
`--color-on-accent` on the `--color-accent` fill when `:checked`. Hover only under `@media (hover: hover)`
and only on the unselected ones. The ring is the base `:focus-visible` rule: the input is the visible
chip, so it needs no ring of its own. In forced colours the fill disappears, so the selected chip is
filled with `Highlight` and its icon `HighlightText`, system colours that the mode keeps. The clicked
chip is its own origin, so the circle starts at its centre.

### Deliberate choices

- **The animation goes through the Web Animations API, not CSS keyframes.** The circle's centre and
  radius are numbers known only at click time. A CSS variable would have to be set on `<html>`, which
  is an inline `style` that `architecture.md` rules out, and a data attribute cannot carry a
  coordinate. The keyframes are two objects in the hook; the duration and easing still come from the
  tokens, read once per transition. There is no `@keyframes`, so nothing is missing from
  `animations.css` for the rule that keeps them there.
- **The saved choice is read in a lazy `useState` initializer, during the first render.** The switch
  must show the saved position on the first paint; an effect would paint "system" first and then
  jump, and `react-hooks` forbids a synchronous `setState` in an effect. `react.md` says nothing
  reads storage during render, so the bullet gets one clause naming this exception (one read, once,
  through the repository).
- **The two browser hooks live in `context/theme/`, private to the provider.** Only the provider calls
  them. In `hooks/` they would make the provider import `@/hooks` while `use-todo-form` imports
  `@/context`: a barrel cycle and a break in the one-way layers. Next to the provider they are
  imported as siblings and never leave the folder; `react.md` gets one line saying where such a hook
  sits.
- **`ThemeRepository` is not a `TodoRepository`.** A different contract (synchronous, one value, no
  list or subscription), and a base class of six `Not implemented` methods has nothing to give it.
- **A click during the circle is lost.** Chrome hit-tests the page as the root while a View Transition
  captures it, and `pointer-events: none` on the pseudo-elements does not change that, so a mouse or
  touch choice within the 200ms of the circle never reaches the switch. A choice by keys does. The
  update itself is never skipped, so nothing is half applied. The author chose `--duration-base` over
  `--duration-slow` to keep that window short.
- **A refused save is an error toast.** The provider that raises the error shows it, as
  `errors-as-toasts` says for storage errors, so the theme context holds no error state and no
  component has to remember to show one.
- **No follow of other tabs.** The tasks need `subscribe` because a stale tab overwrites another tab's
  work; a stale theme overwrites nothing.
- **The `system` position runs the circle too**, even when it changes nothing visible; the snapshots
  are the same, so the circle is invisible, and the code has no special case.
- **`theme-color` stays empty until React starts.** The head script runs before the stylesheet, so it
  cannot read `--color-page`, and a hex literal there is forbidden. Only a phone's address bar can show
  the gap, for the time of the first load.
