## What Vercel does today (read from the live site, nothing there was changed)

- `curl -I /` answers `200`, `Server: Vercel`, an `index.html` built from this repo with no `vercel.json` in it: the
  Vite preset runs the build and serves `dist/`, and pnpm comes from `pnpm-lock.yaml`.
- `curl -I /nope/x` answers `404 Not Found` with `X-Vercel-Error: NOT_FOUND` and a plain-text body, and so does
  `/robots.txt` today. A static deployment answers 404 for a path with no file as long as no `rewrites` exist, and
  the app has no router, so none are needed.

So the plan relies on three things, and each is checked again after the merge: the preset builds `dist/` (it does,
it is live); a path with no file is a real 404 (it is); a file in `public/` is served at the root with its own
content type (the font and `theme.js` already are). Therefore **no `vercel.json`**: there is nothing to pin or rewrite,
and a `rewrites` entry added later would turn every unknown path into a 200 page and break the 404. A custom
`404.html` is not added either: the platform answer already has the right status, and a page would be a screen to
design and keep up. The record below says both.

## Deliberate choices

- **No stored card source.** The card changes about once a year, and a template in the repo (`src/` is built,
  `public/` is published, `ai/` holds docs) is one more file to keep in step with the palette. The skill is the
  recipe for making it again.
- **HTML rendered by Chrome, not a generator package.** The card needs the tokens and the font and nothing else; a
  package such as `satori` or `@vercel/og` is a dependency and a build step for an image that changes once a year
  (`scope.md`: no new dependency). Chrome is already needed for the browser checks.
- **Half in each theme, from two iframes.** The tokens set a theme on `:root[data-theme]` only, so one page cannot
  hold both. The scene is two full-size iframes of two pages, each with its own `data-theme`; the dark one lies below
  and the light one on top, clipped to the bottom-right triangle, so the seam is one edge, not two. The pages take the
  viewport as their size, so the same scene rendered at 1280×640 is the GitHub social preview.
- **Only the list card.** It carries the look of the app and is the part least likely to change; the forms, the
  toolbar and the header can change without making the card untrue. It is remade when the palette, the list card or
  the author's name changes.
- **`og:image` is an absolute URL.** Crawlers do not resolve a relative one. A branch preview therefore shows the
  production card, which exists after the merge; the card does not depend on the branch.
- **The canonical is the root, whatever the query.** The filters live in the URL query; a filtered address is the
  same page, so every one of them names the root as canonical.
- **No `favicon.ico`, no apple touch icon, no manifest, no sitemap.** Browsers and Google read the declared SVG
  icon; a home screen icon and a manifest belong to a PWA, which the project does not have (`scope.md`,
  `rejected-features`). Lighthouse is run to confirm none of them is asked for.
- **A new record and a superseded one.** `vercel-deploy` says the build is pinned in `vercel.json`; with no such
  file that bullet is wrong, and an accepted record must not say it. `ai/decisions/README.md` asks for a new record
  that restates what stays in force, with the old one marked `superseded by`, so it is done that way rather than
  flipping the old status to `accepted`.
