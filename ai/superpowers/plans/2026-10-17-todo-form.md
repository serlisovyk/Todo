### How the form works

- `useTodoForm` owns the three fields (`useState`, each with a `name` in the markup), the focus ref,
  the edit flag and the action, and returns what the markup needs; the action reads the fields from
  its `FormData`. The dot and the flag must follow the selection, and a blocked or failed submit
  must keep the text, so the state is the one truth.
- `<form action>` resets the form after every action, and the reset puts a `<select>` back on its
  first option while its state keeps the old value (the priority showed Low with a Medium flag). The
  form cancels the `reset` event in `onReset`, so the fields only ever change through their state.
- `useActionState(submitTodo, INITIAL_FORM_RESULT)` returns the result of the last submit: an object
  with an `error`, a `status` (each only when there is one) and a counter, `attempt`. `submitTodo`
  blanks the old edit mark, moves focus to the field, rejects a blank title with `isValidTitle`
  (`{ error, attempt }`), otherwise awaits `addTodo`; on a task it clears the title and returns
  `{ status, attempt }`, on `null` it returns `{ attempt }` alone.
- The message is tied to the last submit and is hidden by typing: `hasEdited` is a boolean that the
  title's `onChange` sets and the action clears. During render `isInvalid` is whether there is an
  `error` and the field was not edited, and `message` is the `error`, else the `status`, or nothing
  once the field was edited.
- The live region is `<p role="status" className="sr-only">`; its text sits in a `<span>` keyed by the
  attempt, so a repeated message is a new node and is announced again. The visible error is an
  ordinary `<p id>` under the field, not a live region.
- `PillSelect` is a `<label>` that wraps a `.sr-only` name, a slot for the indicator, the `<select>`
  and a `ChevronDown`; the label wraps the control, so it needs no id. The form puts a dot or a flag
  in the slot and gives it `data-category` or `data-priority`.
- `TodoForm` is markup: it calls the hook, owns the two ids that tie the label and the message to the
  field, and lays the pieces out. Its stylesheet reaches the pills only to let them stretch under
  480px (`.todo-form .pill-select`), the way a parent places its child.

### Deliberate choices

- **The error colour is an alias, `--color-danger`.** No error token exists; reusing
  `--color-priority-high` by name would tie the error to a priority. `#dc2626` is 4.83:1 on the
  surface in the light theme and `#f87171` is 6.4:1 in the dark one, above 4.5:1 for text.
- **`isValidTitle` is reused**, so there is one definition of a usable title; the 200-character limit
  is already enforced by `maxLength`, so only a blank title reaches the message.
- **Focus goes to the field after every submit**, not only on Enter: a click on the button would
  otherwise leave focus on the button (`react.md`: after adding — the input).
- **No pending state.** Both repositories answer in milliseconds; a disabled button would only
  flicker.
- **Select text stays at `--font-size-base`** (16px): a smaller font in a field makes iOS zoom on
  focus.
- **Accent hover is `color-mix` of two tokens** (`--color-accent` with `--color-text`), so it has a
  token-only colour in both themes without a new hex value; `opacity` would drop below 4.5:1.
- **The header centres itself.** It is no longer inside the column that `<main>` forms, so it takes
  the same `max-width`, auto side margins and side padding; a wrapper element would add a node only
  to share three declarations.
