# Plan: search with highlighted matches (MY-155)

Branch `my-155-search`. Linear issue MY-155, milestone Фильтры, after MY-154 (the status filter,
`use-filters`), which is done. It runs in parallel with MY-160 (export and import: a row under the
footer, the todos provider, storage and utils for the backup); the shared files (`app.jsx`, the
barrels, `ai/map.md`) get small local edits. MY-156 builds the category and sort on the same hook.
The spec is `ai/superpowers/specs/2026-10-17-search.md`.

## The author's answers (issue, «Решения автора», 2026-10-16 and 2026-10-17)

All questions are answered, so the work goes from this commit to the code:

- The highlight is a yellow marker, muted in the dark theme. `/` and `Escape` with the hint in the
  placeholder; `/` stays a single-character shortcut that cannot be turned off, a conscious deviation
  from WCAG 2.1.4 that the author accepted and that gets its own record.
- The query is in the URL from the start: `use-filters` reads and writes `?q=` like the status, an
  empty one is not written; MY-156 adds only the category and the sort. The filtering is a pure
  function in `utils/`; the visible list is derived during render.
- The field sits between the add form and the status switch. `/` does nothing inside editable
  fields: `EDITABLE_FIELD_SELECTOR` is reused, and moves to a shared constants file of its own
  domain, since it is no longer only the toast's. The clear button is an `IconButton` named by its
  `title` (decision `tooltips-as-title`, which overrides the `aria-label` of the issue's first
  item). One persistent visually hidden polite region above the list says "N tasks shown" (a correct
  `task` / `tasks`) or "No tasks match your filters" only when the filters change, never on load.
  No debounce.
- The highlight is a pure `utils/highlight.utils.js` that splits the title into parts; matches are
  `<mark>`, case-insensitive, special characters literal. JavaScript budget 90 kB (`main` is 81.44
  kB): report the size.

## Code

Layers and names follow `structure-and-naming`; each new folder gets its `index.js` with its first
file, each new public name is re-exported there.

- `src/constants/filters.constants.js` — `QUERY_PARAM` (`q`), `DEFAULT_QUERY` (an empty string),
  `SEARCH_SHORTCUT_KEY` (`/`), `CLEAR_SEARCH_KEY` (`Escape`), `NO_MATCHES_MESSAGE`, and what the
  highlight needs: `REGEXP_SPECIAL_CHARACTERS`, `REGEXP_ESCAPE_REPLACEMENT`, `MATCH_FLAGS` (`gi`).
- `src/constants/keyboard.constants.js` (new) — `EDITABLE_FIELD_SELECTOR`, moved from
  `toast.constants.js`; `useToastShortcut` and the search shortcut both skip these fields. The
  barrel exports it from the new file; no importer changes.
- `src/utils/filters.utils.js` — `parseFilters` returns `{ status, query }` (the text of `q`, or the
  default), `buildFiltersSearch` writes `q` unless the query is blank (only spaces), and a private
  `matchesQuery` joins `matchesStatus` in `matchesFilters`: the title lowercased contains the trimmed,
  lowercased query. `getFiltersKey(filters)` is the query string of the filters with the query trimmed,
  the key the announcement compares. `useFilters` needs no change: `changeFilters(patch)` already
  merges any patch.
- `src/utils/highlight.utils.js` (new) — `splitByQuery(title, query)` returns the title cut into
  `{ start, text, isMatch }` parts, in order and with no empty one; a blank query returns the whole
  title as one plain part. The match is a `RegExp` built from the trimmed query with its special
  characters escaped and the flags `gi`, run over the original title with `matchAll`, so the offsets
  are the title's own: a character whose lowercase has another length (`İ`) cannot shift a mark, as it
  would in a search over a lowercased copy. `start` is the part's key.
- `src/utils/todos.utils.js` — `getTasksShownMessage(count)` beside the other counter messages, over
  the same `formatTaskCount`; zero is `NO_MATCHES_MESSAGE`.
- `src/hooks/use-search-field.js` (new) — `useSearchField()`: the field's logic. It reads and changes
  the query through `useFilters`, keeps the input ref, and registers the `/` shortcut on the
  document in an effect that removes it in its cleanup; `handleKeyDown` clears on `Escape`,
  `handleClear` focuses the input first and then clears, because the button leaves with the text.
- `src/hooks/use-filter-announcement.js` (new) — `useFilterAnnouncement()`: the message and its key,
  see the choices below.
- `src/hooks/use-todo-item.js` — returns `titleParts`, the title cut by the query. `stopEditing`
  takes the fields that were saved, checks the task with them applied against the filters and, when
  it no longer matches, focuses the neighbour the lookup of delete finds instead of the edit button,
  found before the row can go. `src/hooks/use-todo-edit.js` — `saveChanges` returns the saved fields
  (none when nothing was saved) and `saveAction` passes them to `onClose`.
- `src/components/search-field/` (new) — `SearchField`: a `div` with the hidden `<label>`, the `Search`
  icon, an `<input type="search">` and, while there is text, an `IconButton` with `X` and the
  `labelText` "Clear search". `search-field.css`: the field is outlined like the add form's title
  field, the icon and the button are absolutely placed inside it (the button through
  `.search-field .icon-button`, like `.todo-form .pill-select`), the input keeps room for both; the
  native cancel button of the search type is hidden, because the field has its own.
- `src/components/filter-announcer/` (new) — `FilterAnnouncer`: the `role="status"` `.sr-only`
  paragraph with the message in a `<span>` keyed by the change, the same shape as the add form's
  message. No stylesheet: it only uses `.sr-only`.
- `src/components/todo-item/` — the title renders its parts, `<mark className="todo-item-mark">` for
  a match and text for the rest; the mark has `--color-highlight` and `--color-on-highlight`, and in
  forced colours `Highlight`, `HighlightText` and `forced-color-adjust: none`. `tokens.css` gives
  the dark theme its own values for the two tokens: a muted dark gold with near-white text.
- `src/components/app/app.jsx` — `<SearchField />` between the form and the switch,
  `<FilterAnnouncer />` between the switch and the list.

## Deliberate choices

- **The URL and the field hold the query as typed; the trim happens where it is used.** The field is
  controlled by the URL, so a trimmed value would swallow the space typed between two words. The
  filter, the highlight and the announcement trim; the URL leaves a blank query out, so " " leaves
  nothing behind.
- **The announcement is state that changes when the filters change, not a derived message.** A message
  derived from the current count would be read again on every change of the tasks (a delete, a
  toggle), which the toast and the counter already announce. The hook keeps
  `{ filtersKey, message, attempt }` and replaces it during render when the filters' key differs from
  the one kept (the pattern React documents for state that follows a change); the message is the one for the count at that
  moment, so it stays as it is until the filters change again. An effect on the filters event cannot
  do it: it runs before the render that has the new filters, so it does not know their count. A
  `<span>` keyed by `attempt` makes a repeated result be read again, as the rule for repeating messages
  says; `attempt` starts at 0 with no message, so load is silent, also with a query in the URL.
- **The region is its own component in `App`, not part of `TodoList`.** `TodoList` returns early for
  loading and the two empty texts, and the region must stay in the page through all of them.
- **A region of its own, next to the counter and the toast.** The filter result is a third event, not
  the toast's and not the counter's; `react.md` says so in the line about the counter.
- **Highlighting by a regular expression over the original title.** Rejected: `indexOf` over a
  lowercased copy, whose offsets drift for a few Unicode characters; and `dangerouslySetInnerHTML`,
  which the decision forbids.
- **`type="search"`.** It tells assistive technology what the field is; the native cancel button and
  the platform styling are switched off, and Escape is handled in the app because not every browser
  clears a search field on it.
- **The clear button is rendered only with text** (not hidden), like the mark-all buttons: a button
  that does nothing is not offered.
- **An edit that unmatches the query moves the focus first.** The same reason as a toggle under a
  status filter and a delete: otherwise the focus falls to the page when the row goes. The check
  takes every saved field, not only the title, so a filter on another field needs no change here.
- **No `aria-label`, no `title` on the field.** The hidden label names it; a `title` beside it would
  be read twice (`tooltips-as-title`). The placeholder carries the visible hint, `aria-keyshortcuts`
  the machine-readable one, as the toast's button does for Ctrl/Cmd+Z.
