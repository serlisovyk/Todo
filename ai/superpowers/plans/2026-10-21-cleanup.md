## What was measured first

- A tap in Chromium's touch emulation fires `pointerdown`, `pointerup`, `touchend`, and only then the emulated

## Decisions taken in this plan

- **Hold the form while a mouse button is down: a ref set by `mousedown` and cleared by `mouseup`, not by the pointer
  events.** The issue names `pointerdown` and `pointerup`; the measurement above shows that for a tap they are over before
  the blur, so the tap would be lost. `mousedown` and `mouseup` are the events the blur belongs to, for a mouse and for the
  emulated ones of a tap. They are listened to on the document in the capture phase, so a handler that stops propagation
  cannot hide them. The hook is `useMousePressed` in `hooks/`, private to it, returning the ref.
- **Close on the click that follows.** In `handleBlur`, with no button down the form closes at once; with one down
  it adds `document.addEventListener('click', close, { once: true })`, which runs after the clicked control's own React
  handler (React listens on the root, below the document) and after its default action has been decided. No timer
  is left. The toast's capture-phase click guard (`useToastExit`) swallows only repeated clicks, and only until the
  first fresh one; the form's listener is in the bubble phase, so a swallowed click leaves it armed for the next
  click, and a fresh one is never held back by the guard.
- **`useTodoFields(initial)` is private to `hooks/`** (it is not in the barrel, like `useBackupDownload`): the add and the
  edit hook import it from a sibling. It owns `titleInputRef`, the three values, their setters and `handleTitleChange`
  (the `limitTitle` cut). `initial` is an object with `title`, `category` and `priority`: the add form passes
  `NEW_TODO_FIELDS` (a constant in `todos.constants.js`), the edit form the task itself. The add form wraps
  `handleTitleChange` to mark the field edited; everything else stays in each form's own hook.
- **`HighlightedText({ text, query })`** is a component of its own (`components/highlighted-text/`), calls `splitByQuery` and
  returns the plain parts and the `<mark>`s. The rule for the mark moves with it from `todo-item.css` into
  `highlighted-text.css` (`.highlighted-text-mark`), since a class takes its component's name. `useTodoItem` returns
  `query` instead of `titleParts`.
- **Focus by refs.** `TodoList` owns `checkboxesRef`, a `Map` from a task id to its checkbox element, and gives each
  row the id of its neighbour (the next task, else the previous one, in the order it renders) and the `Map`. The row
  registers its checkbox through a ref callback that returns its cleanup, so a row in edit mode has no entry. The target after a
  delete, a toggle or an edit that hides the row is the neighbour's checkbox, else the checked status radio (a DOM query,
  as the issue allows): the same answer as `nextElementSibling ?? previousElementSibling` gave, including a neighbour in
  edit mode, which has no checkbox and so sends the focus to the radio. The target is resolved before the row changes
  and focused after `flushSync` where it is today. Undo focuses the restored row's checkbox through the same `Map`, so
  `getTodoCheckboxId`, the checkbox's `id` and `TODO_CHECKBOX_SELECTOR` have no user left and go.
- **Barrels re-export a module by name up to four names and with `export * from` above four.** Applied to `utils/` and
  `constants/` (every other barrel line exports one to three names). The set of public names is unchanged: a script
  compares the names exported before and after, and checks the modules re-exported with `*` for clashes. It is its own
  commit, first after the plan, so a rebase onto MY-172's barrel lines is one conflict, resolved by taking `export *`.
- **`parseJson`** moves to `json.utils.js` unchanged and joins the `utils/` barrel as a shared name.
- **`styles/animations.css`** holds only the cross-fade reset of the View Transition: it moves to the end of `base.css` and
  the file goes, with its import in `style.css`. There is no `@keyframes` in the project; `base.css` takes over the rule
  too (the author's answer): every `@keyframes` and every `::view-transition-*` rule lives there, the one shared home.
- **Two decision records:** the barrel rule, and "order work by events and refs, not by timers and DOM walks", which
  holds the mouse-versus-pointer finding a later cleanup could undo.
