## Deliberate choices

- **Tokens.** The scale has no 500 ms and no ease-in-out, so `--duration-slower: 500ms` and
  `--ease-in-out: ease-in-out` are added; `TRANSITION_DURATION_VARIABLE` and `TRANSITION_EASING_VARIABLE`
  point at them and `useCircleTransition` reads them as before. The toast uses `--duration-base`
  (200 ms): the scale has no 250 ms and one more token for 50 ms would only clutter it; it is the
  duration of every other transition here.
- **"Active" is the selected chip.** The theme chips have no pressed look, and one is not added (out of
  scope); the chip that becomes selected changes its background and its icon colour on the same
  transition as hover.
- **Transitions are written per rule, reduced motion once.** Each rule names its properties and uses
  `--duration-base` and `--ease-out`. `tokens.css` has the one `prefers-reduced-motion` block, which sets
  every `--duration-*` to 0ms, so a transition does not run and no component repeats the block; the pill's
  open list loses its own. A transition that does not run sends no `transitionend`, so the toast's exit
  and the circle check the query in the script.
- **A theme change does not fight the transitions.** The colours of every transitioning element change
  with the theme, and the new view of the page is live, so a button could fade from the old colours
  inside the revealed circle. Checked by pausing the transition at sampled times: the circle reaches an
  element after that element's 200 ms transition has all but ended, and only the theme chips, next to
  the click, are seen changing, which is the point of the smooth selected state. Nothing is added.
- **`IconButton` is a component.** The pencil, the trash, `Check` and `X` are the same 44px button with an
  icon, a name and a hover colour; without a component the edit form would copy the row's rules, and
  each button would repeat its name and tooltip. `IconButton` takes `Icon`, `labelText` and `tone`
  (`danger` for the trash), sets `title` from `labelText` and passes the rest (`ref`, `type`, `onClick`,
  `onMouseDown`) to the `<button>`; `type` is `button` unless the caller says otherwise. The row loses
  its `.todo-item-action*` rules.
- **Vertical centring is one declaration**, `align-self: center` on the row's actions; the wrap rules of
  the row are untouched.
- **The tooltip.** The premise that the browser does not make a `title` equal to the name a description
  is false in Chrome 155: with `aria-label="X"` and `title="X"` the accessibility tree lists the name
  `X` and the description `X`, and so for a radio or a select named by a label with `title` on the
  control. What leaves one reading, checked in the tree: a `title` on the `<label>` that wraps the
  control gives no description to the control, and a button named by its `title` alone has no
  description. So the chip's and the pill's `<label>` carries `title` (the pointer over the chip or the
  pill is inside the label, so the tooltip shows), their names still come from the hidden label, and an
  icon button has `title` as its name and no `aria-label`. The rules say so. Rejected: `aria-label` and
  `title` together (a description equal to the name), an empty `aria-description` or an `aria-describedby`
  to an empty element (tricks that rely on one browser), and a `title` on an inner element (the
  tooltip would show only over the icon).
- **The toast leaves in `useToastExit`.** The hook holds `isLeaving`, `dismiss` (starts the exit; with
  reduced motion it removes the toast at once, found with `matchMedia` in the handler as
  `useCircleTransition` does) and `handleTransitionEnd` (removes the toast when the exit transition of the toast
  itself ends, not the entry's, which also ends on the toast, and not a child's). `Toast` passes `dismiss` to the timer and to its action, takes `inert`
  and `is-leaving` while it leaves, and gives the shortcut no action then, so a second Undo or a second
  Ctrl+Z during the exit does nothing. The region keys the toast by its id, so a replacement unmounts the
  leaving one at once. `REDUCED_MOTION_QUERY` moves from `theme.constants.js` to `css.constants.js`: it is
  no longer a theme value.
- **The edit form puts Save and Cancel last**, in an actions block with `margin-inline-start: auto`, so
  the title keeps its full width at every size and the buttons share the pills' line when they fit. Save is
  a `type="submit"` button of the form, so the form's own action saves, as Enter does (Enter in the title
  presses the first submit button, which is Save); Cancel is a `type="button"` that closes with the focus
  on the pencil, as Esc does.
- **Cancel never saves.** The form saves when the focus leaves it, and Safari does not focus a button
  on a click, so the title's blur would carry no `relatedTarget` and save before the click. Both buttons
  call `preventDefault` on `mousedown`, which keeps the focus where it was: no blur, so no save, in every
  browser; a tap fires the same `mousedown`. In Chrome, where a click focuses the button, the blur has the
  button as `relatedTarget` and is ignored as before.
