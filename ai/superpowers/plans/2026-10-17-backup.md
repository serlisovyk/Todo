## Code

Layers follow `architecture.md`; each new file is re-exported from its folder's `index.js`.

- `src/constants/backup.constants.js` (new, re-exported by `constants/index.js`): the app name in the file
  (`todo`), the file name parts, the MIME type and the `accept` value, the size limit (1 MB, derived from a
  megabyte count the message also uses), the date locale for the file name, how long the object URL lives,
  and the messages (not a backup, too large, unreadable, no tasks).
- `src/utils/backup.utils.js` (new), all pure:
  - `buildBackup(todos, exportedAt)`: the object that is written, `exportedAt` given by the caller so the
    function reads no clock;
  - `getBackupFileName(date)`: `todo-backup-YYYY-MM-DD.json` from the local date;
  - `parseBackup(text)`: the whole-file check; the `todos` array, or `null` for anything that is not a
    backup, the JSON error included;
  - `splitBackupTodos(values, storedTodos)`: through `sanitizeTodos`, then by id against the stored tasks and
    the ones already taken from the file (a `Set`): `{ newTodos, existingCount, skippedCount }`;
  - `getImportMessage(counts)`: the summary over the existing `formatTaskCount`, which `todos.utils.js` now
    exports (and the barrel re-exports) instead of keeping it private.
- `src/hooks/use-todo-backup.js` (new): the DOM parts and the flow. `handleExport` builds the object, a `Blob`
  and an object URL, clicks an `<a download>` and revokes the URL later; `handleImportClick` clicks the hidden
  input; `handleFileChange` takes the file, resets the input, and runs: size check, `file.text()`,
  `parseBackup`, `splitBackupTodos` against `todos`, `restoreTodos(newTodos)`, the summary toast. Errors are
  `showToast({ message, isError: true })`.
- `src/context/todos/todos.provider.jsx`: no new action. `restoreTodos` already writes tasks back unchanged,
  shows the error toast and rolls the list back when the write is refused, but resolves to nothing; it now
  resolves to `isSaved`, so a caller knows whether the write held, and its parameter is named
  `restoredTodos`, since Undo is not its only caller. The Undo callers ignore the value.
- `src/components/text-button/` (new, its own commit): `TextButton`, modelled on `IconButton`: children are
  the label, `type` defaults to `button`, every other prop (a ref too) goes to the `<button>`; no `className`
  and no variants. `text-button.css` is the footer's look. The footer's three buttons and the toast's action
  use it and their own classes go; the toast keeps its action at the end, also when it wraps, with
  `justify-content: flex-end` on its own layout.
- `src/components/todo-backup/` (new): `TodoBackup`, a `<div role="group" aria-label="Backup">` with Export
  (only with tasks) and Import as `TextButton`s and the hidden `<input type="file">`; `todo-backup.css` has
  only the row. `components/index.js` re-exports it and `app.jsx` renders it after `<TodoFooter />`.

## Deliberate choices

- **The existing `restore`, not a new repository method and no new context action.** The issue asks for it;
  it already skips stored ids, validates each task and rejects as one write, so nothing is half-written.
  The split counts the summary needs are worked out before the call from the tasks the context holds; if
  another tab added a task in the milliseconds between, `restore` still skips it and only the count is off.
- **The file name uses the local date, `exportedAt` the UTC time.** A person who exports at 01:00 expects
  today's date in the name.
- **Compact JSON.** A backup is read by the import; compact output fits more tasks under the 1 MB limit.
- **A repeated `id` inside the file counts as "already there".** The repository's `restore` does not
  de-duplicate within one call (localStorage would store two tasks with one `id`, IndexedDB would abort), so
  the split does it.
- **A hidden input driven by the button.** The `<button>` is the control; the input has `hidden`, so it is
  neither focusable nor read twice. `value` is cleared after each choice so choosing the same file again
  fires `change`.
- **Export has no toast, an import always has one.** Export changes nothing in the app; an import changes
  the list, and it has to say how much.
- **One `TextButton` instead of three copies of one rule.** The footer, the toast and the row drew the
  same button. The toast's was a little larger (base font size, wider padding); it takes the footer's
  look, since the difference carried no meaning, and its 44px touch target stays.
- **The size limit is `file.size`,** checked before reading, so a huge file is never loaded into memory.
