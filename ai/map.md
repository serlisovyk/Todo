# Repo map

Navigation only: where things live and who owns what. How it works is in the code, why in `ai/decisions/`.
Update it when a file, folder, storage key or script is added, renamed or removed (`ai/rules/docs.md`).

## Repo

- `index.html` — the page Vite serves and builds: the `theme-color` meta, the description, canonical, icon, Open
  Graph and Twitter tags, the blocking `theme.js` script, the font preload, `#root`, the `src/main.jsx` entry.
- `src/` — all sources (below). `dist/` — generated by `pnpm build`; never edited.
- `public/` — files served as they are under a stable URL: `fonts/inter.woff2` (Inter, Latin), `theme.js` (the head
  script that sets `data-theme` before the first paint), `favicon.svg`, `og-image.png`, `robots.txt` and `llms.txt`.
- `assets/` — the README's demo GIF; it is not built, served or imported.
- `vite.config.js` — the React plugin, the React Compiler through `@rolldown/plugin-babel`, the `@/` alias.
- `jsconfig.json` — the `@/` alias for editors only.
- `.env.sample` — the one environment variable, `VITE_STORAGE`: `localstorage` (the default) or `indexeddb`.
- `eslint.config.js` — flat config: React Hooks, React Refresh, `jsx-a11y`, file names, named exports,
  imports, storage access; also enforces `ai/rules/`.
- `.prettierrc` — the workspace Prettier config; `.prettierignore` — `node_modules`, the lockfile, `dist`, `.claude`.
- `.lintstagedrc.json` + `.husky/pre-commit` — ESLint and Prettier on staged files before each commit.
- `.size-limit.json` — the budgets: gzip for the built JavaScript and CSS, raw bytes for the font.
- `.github/workflows/ci.yml` — CI on every push: lint, format check, build, size.
- `package.json` — scripts `dev`, `build`, `preview`, `size`, `lint`, `lint:fix`, `format`,
  `format:check`, `prepare` (installs the hook); `pnpm-lock.yaml` is the lockfile.
- `pnpm-workspace.yaml` — pnpm settings: the allowed ESLint peer of `jsx-a11y`.
- `AGENTS.md` — the entry point for agents; `CLAUDE.md` points to it.
- `ai/` — agent docs: this map, `workflow.md`, `rules/`, `skills/`, `decisions/`, `prompts/`,
  `linear-task-template.md`.
- `ai/superpowers/` — the archive of plans and specs: read only the plan or spec of the feature you change.
- `.claude/worktrees/` — one git worktree per task when tasks run in parallel; ignored by git.

## Sources (`src/`)

- `main.jsx` — the entry point and the only `createRoot`: imports `App` and `styles/style.css`,
  renders `App` in `StrictMode`.
- `components/app/` — `App`, the root component: `ErrorBoundary` around the three providers, the page header,
  `<main>` and the toast region; `components/index.js` re-exports every component.
- `components/app-header/` — `AppHeader`: the page `<header>`, a banner outside `<main>`, with the logo, the `<h1>`
  and the theme switch.
- `components/category-dot/` — `CategoryDot`: the 12px dot in a category's colour (the forms and the category pill).
- `components/error-boundary/` — `ErrorBoundary`, the one class component: after a render error below it, it shows
  `ErrorScreen`.
- `components/error-screen/` — `ErrorScreen`: the heading, Export backup (the tasks read straight from the
  repository) and Reload; its logic is `useErrorScreen`.
- `components/filter-announcer/` — `FilterAnnouncer`: the persistent visually hidden live region above the list;
  it says what the filters show; its logic is `useFilterAnnouncement`.
- `components/filters-toolbar/` — `FiltersToolbar`: the search field and, under it, the Category and Sort pills and
  Reset filters; its logic is `useFiltersToolbar`.
- `components/icon-button/` — `IconButton`: a 44px icon-only button named by its `title`.
- `components/pill-select/` — `PillSelect`: a native `<select>` in a pill; `renderMark` draws its dot, flag or
  icon, also inside each option of the open list; `ref` reaches the `<select>`.
- `components/search-field/` — `SearchField`: the labelled search input and its clear button; its logic is
  `useSearchField`.
- `components/status-switch/` — `StatusSwitch`: three radio buttons (All, Active, Completed) that set the status filter.
- `components/text-button/` — `TextButton`: the one text button (the footer, the toast's action, the backup row).
- `components/theme-switch/` — `ThemeSwitch`: three radio buttons (sun, moon, monitor) that set the theme.
- `components/todo-form/` — `TodoForm`: the markup of the add-task form; its logic is `useTodoForm`.
- `components/todo-list/`, `components/todo-item/` — the tasks area (the loading text, the two empty texts, the
  rows `filterTodos` shows in `sortTodos` order) and one row (checkbox, title with `<mark>` matches, meta, buttons).
- `components/todo-footer/` — `TodoFooter`: under the list, the tasks-left counter, the mark-all buttons and
  Clear completed; its logic is `useTodoFooter`.
- `components/todo-backup/` — `TodoBackup`: the "Backup" group at the end of `<main>`: Export (while tasks exist),
  Import and its hidden file input; its logic is `useTodoBackup`.
- `components/todo-edit-form/` — `TodoEditForm`: a row's edit form (title, category, priority, Save and Cancel).
- `components/toast-region/`, `components/toast/` — `ToastRegion`: the always-present `role="status"`
  region; `Toast`: the message (with an error icon) and its action button.
- `hooks/` — each component's logic as `use<Component>`, and the browser-API hooks: `useFilters` (the filters in
  the URL query), `useSearchField` (the field and the `/` shortcut), `useToastShortcut` (Ctrl/Cmd+Z runs the
  toast's action), `useBackupDownload` (the backup file's download; private to `hooks/`); barrel `index.js`.
- `constants/` — a `<domain>.constants.js` per domain: `storage` (keys, version, storage messages), `todos`,
  `filters`, `keyboard`, `toast`, `backup`, `theme`, `css`; barrel `index.js`.
- `utils/` — `todos.utils.js` (`sanitizeTodo`, `sanitizeTodos`, `isValidTitle`: the one task validator; the pure
  list transforms the context applies; `sortTodos`: the order a sort names; the counter, toast and filter-result
  messages), `filters.utils.js` (`filterTodos`, and `parseFilters` and `buildFiltersSearch` between the URL query
  and the filters), `highlight.utils.js` (`splitByQuery`), `theme.utils.js` (`isTheme`, `resolveTheme`),
  `css.utils.js` (`toMilliseconds`), `backup.utils.js` (the pure side of export and import: the file's object and
  name, `parseBackup`, `splitBackupTodos`, the summary), `validation.utils.js` (general checks); barrel `index.js`.
- `storage/` — `TodoRepository` (the contract and the helpers its implementations share),
  `LocalStorageRepository`, `IndexedDbRepository`, `createRepository` (picks the implementation by `VITE_STORAGE`,
  asks for persistent storage), `ThemeRepository` (the saved theme). The barrel exports the last two.
- `context/todos/` — `TodosProvider` and `useTodos` (the only public names; `TodosContext` stays
  inside): the tasks, `isLoading` and the actions over the repository; a failed write or read is a toast.
- `context/toast/` — `ToastProvider` and `useToast`: the one toast, `showToast` and `dismissToast`.
- `context/theme/` — `ThemeProvider` and `useTheme`: the choice and `changeTheme`; it also sets `data-theme`
  and the `theme-color` meta, and a refused save is a toast. `useMediaQuery` and `useCircleTransition` (a
  circle reveal in a View Transition) are private to it. `context/index.js` re-exports each context folder.
- `styles/style.css` — the one stylesheet entry: imports the files below in order.
- `styles/tokens.css` — every colour for both themes and the scales (spacing, radii, type,
  durations, easings, focus ring); under reduced motion it zeroes the durations.
- `styles/colors.css` — `[data-category]` and `[data-priority]` set `--category-color` and
  `--priority-color` from the colour tokens.
- `styles/base.css` — the Inter face, box sizing, `body`, the focus ring, `.sr-only`.
- `styles/animations.css` — the theme's View Transition rules; every `@keyframes` goes here too.

The layout (decisions `structure-and-naming`, `context-folders`). A folder appears with its first file; a folder of
JavaScript modules has an `index.js` of named exports; code imports across folders through `@/`:

| Folder        | Holds                                                                  |
| ------------- | ---------------------------------------------------------------------- |
| `components/` | a folder per component: `.jsx`, `index.js`, `.css`                     |
| `context/`    | a folder per context: object, provider and its hook                    |
| `hooks/`      | `use-*` hooks not tied to a context: browser APIs, a component's logic |
| `storage/`    | `TodoRepository` and its implementations                               |
| `utils/`      | pure functions: filtering, sorting, validation                         |
| `constants/`  | shared values: storage keys, categories, priorities                    |
| `styles/`     | tokens, colour mapping, base styles, every `@keyframes`                |

`styles/` has no `index.js`: `style.css` imports its stylesheets, and `main.jsx` imports `style.css`.

## Storage

Every access goes through `storage/` (decision `repository-storage-restore`); the theme script in `<head>` is
the one reader outside it (decision `theme-head-script`).

| Key          | Holds                                  | Written by                                   |
| ------------ | -------------------------------------- | -------------------------------------------- |
| `todo:data`  | `{ version, todos }` with localStorage | `LocalStorageRepository`                     |
| `todo:theme` | `light`, `dark` or `system`            | `ThemeRepository` (the head script reads it) |

With `VITE_STORAGE=indexeddb` the tasks live in the IndexedDB database `todo`, store `todos`, keyed by `id`;
other tabs hear about a write on `BroadcastChannel('todo')`.

The app keeps no backup file: export writes `todo-backup-YYYY-MM-DD.json` with the version `todo:data` carries,
and import merges it by `id` through `restore`, in either backend (decision `backup-export-import`).

## Where is the recipe

- A feature, a component, a filter, a toast, an animation: `ai/skills/feature.md`.
- A repository implementation or a change to the stored format: `ai/skills/storage.md`.
- Reviewing a diff: `ai/skills/review.md`.
- A new link preview card, the favicon's colours: `ai/skills/og-image.md`.
- What must hold: `ai/rules/`. Why it is so: `ai/decisions/` (index in its `README.md`).
- Starting an agent session: `ai/prompts/`. Writing a Linear issue: `ai/linear-task-template.md`.

## Deployment

Live at <https://todo-plum-nu-78.vercel.app/> on Vercel through its Git integration: `main` is production, other
branches get previews, and there is no `vercel.json` (decision `vercel-and-link-previews`).

## Not in this project

- No TypeScript and no automated tests: decisions `react-and-javascript`, `no-automated-tests`.
- No state manager and no `useReducer`: decision `state-in-context-and-hooks`.
- No backend, HTTP API, authentication or analytics: `ai/rules/scope.md`.
- No pull requests: work merges locally (decision `local-merge-without-pr`).
- No due dates, custom categories, drag and drop, subtasks, recurring tasks, reminders, PWA or i18n:
  decision `rejected-features`.
