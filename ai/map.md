# Repo map

Navigation only: where things live and who owns what. How it works is in the code, why in `ai/decisions/`.

## Repo

- `index.html` — Vite's entry page: the SEO, Open Graph and Twitter tags, the two `theme-color` metas, the blocking
  `theme.js`, the font preload, `#root`, `src/main.jsx`.
- `src/` — all sources (below). `dist/` — generated by `pnpm build`; never edited.
- `public/` — files served as they are, under a stable URL (`ai/rules/assets-performance.md`): `fonts/inter.woff2`,
  `theme.js`, `favicon.svg`, `og-image.png`, `robots.txt`, `llms.txt`.
- `assets/` — the README's demo GIF, not built or served.
- `vite.config.js` — the React plugin, the React Compiler through `@rolldown/plugin-babel`, the `@/` alias;
  `jsconfig.json` — the alias for editors only.
- `.env.sample` — the one environment variable, `VITE_STORAGE`: `localstorage` (the default) or `indexeddb`.
- `eslint.config.js` — flat config: React Hooks, React Refresh, `jsx-a11y`, file names, named exports,
  imports, storage access; also enforces `ai/rules/`.
- `.prettierrc`, `.prettierignore` — the workspace Prettier config.
- `.lintstagedrc.json` + `.husky/pre-commit` — ESLint and Prettier on staged files before each commit.
- `.size-limit.json` — the budgets (gzip for JavaScript and CSS, raw bytes for the font).
- `.github/workflows/ci.yml` — CI on every push: lint, format check, build, size.
- `package.json` — scripts `dev`, `build`, `preview`, `size`, `lint`, `lint:fix`, `format`, `format:check`,
  `prepare` (installs the hook); `engines` (Node) and `packageManager` (pnpm) pin the tools.
- `pnpm-lock.yaml` — the lockfile; `pnpm-workspace.yaml` — pnpm settings: the allowed ESLint peer of `jsx-a11y`.
- `AGENTS.md` — the entry point for agents; `CLAUDE.md` points to it.
- `ai/` — agent docs: this map, `workflow.md`, `rules/`, `skills/`, `decisions/`, `prompts/`,
  `linear-task-template.md`, and the archive `superpowers/`.
- `.claude/worktrees/` — one git worktree per task when tasks run in parallel; ignored by git.

## Sources (`src/`)

Layers: `ai/rules/architecture.md`. Naming, barrels and `@/`: `ai/rules/style.md`; every folder of modules has a barrel.

- `main.jsx` — the entry point and the only `createRoot`: renders `App` in `StrictMode`, imports `styles/style.css`.
- `components/app/` — `App`, the root: `ErrorBoundary` around the three providers, header, `<main>`, footer, toast region.
- `components/app-header/` — `AppHeader`: the page `<header>` outside `<main>`: the logo, the `<h1>`, the theme
  switch and the repository link.
- `components/app-footer/` — `AppFooter`: the page `<footer>` outside `<main>`: the author's name and the year.
- `components/github-link/`, `components/github-icon/` — `GithubLink`: the header's 44px icon link to the
  repository; `GithubIcon`: the mark `lucide-react` lacks.
- `components/category-dot/` — `CategoryDot`: the 12px dot in a category's colour (the forms and the category pill).
- `components/error-boundary/` — `ErrorBoundary`, the one class component: after a render error below it shows `ErrorScreen`.
- `components/error-screen/` — `ErrorScreen`: the heading, Export backup (the tasks read straight from the
  repository) and Reload; its logic is `useErrorScreen`.
- `components/filter-announcer/` — `FilterAnnouncer`: the hidden live region above the list that says what the
  filters show; its logic is `useFilterAnnouncement`.
- `components/filters-toolbar/` — `FiltersToolbar`: the search field and, under it, the Category and Sort pills and
  Reset filters; its logic is `useFiltersToolbar`.
- `components/highlighted-text/` — `HighlightedText`: a text with its query matches in `<mark>`.
- `components/icon-button/` — `IconButton`: a 44px icon-only button named by its `title`.
- `components/pill-select/` — `PillSelect`: a native `<select>` in a pill; `renderMark` draws its dot, flag or icon
  in the pill and in each option of the open list; `ref` reaches the `<select>`.
- `components/search-field/` — `SearchField`: the labelled search input and its clear button; its logic is `useSearchField`.
- `components/status-switch/` — `StatusSwitch`: three radio buttons (All, Active, Completed) that set the status
  filter, each with its task count.
- `components/text-button/` — `TextButton`: the one text button (the footer, the toast, the backup row, the error screen).
- `components/theme-switch/` — `ThemeSwitch`: three radio buttons (sun, moon, monitor) that set the theme.
- `components/title-counter/` — `TitleCounter`: the `N / 200` under a title field near the limit and its own status.
- `components/todo-form/` — `TodoForm`: the markup of the add-task form; its logic is `useTodoForm`.
- `components/todo-list/`, `components/todo-item/` — `TodoList`: the loading and empty texts and the rows
  `filterTodos` shows in `sortTodos` order; `TodoItem`: one row.
- `components/todo-footer/` — `TodoFooter`: under the list, the tasks-left counter, the mark-all buttons and
  Clear completed; its logic is `useTodoFooter`.
- `components/todo-backup/` — `TodoBackup`: the "Backup" group at the end of `<main>`: Export (while tasks exist),
  Import and its hidden file input; its logic is `useTodoBackup`.
- `components/todo-edit-form/` — `TodoEditForm`: a row's edit form (title, category, priority, Save and Cancel).
- `components/toast-region/`, `components/toast/` — `ToastRegion`: the always-present `role="status"`
  region; `Toast`: the message (with an error icon) and its action button.
- `hooks/` — each component's logic as `use<Component>`, and the browser-API hooks:
  - public: `useFilters` (the filters in the URL query), `useSearchField` (the field and the `/` shortcut),
    `useToastShortcut` (Ctrl/Cmd+Z runs the toast's action);
  - private to `hooks/`: `useTodoFields` (the fields of both forms), `useMousePressed` (a held mouse button),
    `useBackupDownload` (the backup file's download).
- `constants/` — a `<domain>.constants.js` each: `storage` (keys, version, messages), `todos`, `filters`, `keyboard`,
  `toast`, `backup`, `theme`, `css`, `events`, `app` (author, repository link).
- `utils/` — one `<domain>.utils.js` each, all pure:
  - `todos`: `sanitizeTodo` and `isValidTitle` (the one task validator), `limitTitle` (its cut), the list transforms
    the context applies, `sortTodos`, the task-count and title-counter messages;
  - `filters`: `filterTodos`, `parseFilters` and `buildFiltersSearch` (the URL query and the filters), the category
    and status options with their counts, the empty-list message;
  - `backup` (the pure side of export and import), `highlight` (`splitByQuery`), `theme`, `css`, `events`
    (`isRepeatedClick`), `json`, `validation`.
- `storage/` — the barrel exports only `createRepository` (picks the implementation by `VITE_STORAGE`, asks for
  persistent storage) and `ThemeRepository` (the saved theme):
  - `TodoRepository` — the contract and the helpers its implementations share; `LocalStorageRepository`,
    `IndexedDbRepository`.
- `context/todos/` — `TodosProvider` and `useTodos` (the only public names): the tasks, `isLoading` and the actions
  over the repository; a failed write or read is a toast.
- `context/toast/` — `ToastProvider` and `useToast`: the one toast, `showToast` and `dismissToast`.
- `context/theme/` — `ThemeProvider` and `useTheme`: the choice and `changeTheme`; it sets `data-theme` and both
  `theme-color` metas, and a refused save is a toast.
  - private to it: `useMediaQuery` and `useCircleTransition` (a circle reveal in a View Transition).
- `styles/style.css` — the one stylesheet entry: imports the files below in order.
- `styles/tokens.css` — every colour for both themes and the scales (spacing, radii, type,
  durations, easings, focus ring); under reduced motion it zeroes the durations.
- `styles/colors.css` — `[data-category]` and `[data-priority]` set `--category-color` and
  `--priority-color` from the colour tokens.
- `styles/base.css` — the Inter face, box sizing, `body`, `#root` (a column as tall as the window), the focus ring,
  `.sr-only`, the theme's View Transition cross-fade reset.

## Storage

Every access goes through `storage/` (decision `repository-storage-restore`); the theme script in `<head>` is
the one reader outside it (decision `theme-head-script`).

| Key          | Holds                                  | Written by                                   |
| ------------ | -------------------------------------- | -------------------------------------------- |
| `todo:data`  | `{ version, todos }` with localStorage | `LocalStorageRepository`                     |
| `todo:theme` | `light`, `dark` or `system`            | `ThemeRepository` (the head script reads it) |

With `VITE_STORAGE=indexeddb` the tasks live in the IndexedDB database `todo`, store `todos`, keyed by `id`;
other tabs hear about a write on `BroadcastChannel('todo')`.

The app keeps no backup file: export writes `todo-backup-YYYY-MM-DD.json` with the version `todo:data` carries,
and import merges it by `id` through `restore`, in either backend (decision `backup-export-import`).

## Deployment

Live at <https://todo-plum-nu-78.vercel.app/> on Vercel through its Git integration: `main` is production, other
branches get previews, and there is no `vercel.json` (decision `vercel-and-link-previews`).

## Not in this project

- No TypeScript and no automated tests: decisions `react-and-javascript`, `no-automated-tests`.
- No state manager and no `useReducer`: decision `state-in-context-and-hooks`.
- No backend, HTTP API, authentication or analytics: `ai/rules/scope.md`.
- No pull requests: work merges locally (decision `local-merge-without-pr`).
- No due dates, custom categories, drag and drop, subtasks, recurring tasks, reminders, PWA or i18n:
  decision `rejected-features`.
